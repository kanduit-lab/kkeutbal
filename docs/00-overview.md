## Problem

MT·모임에서 친구들끼리 **돈을 걸지 않고** 화투(섯다·고스톱)나 포커를 할 때:

1. 칩을 공용으로 쓰기 때문에 누가 얼마를 땄는지 판이 끝나면 알 수 없다.
2. 승패 기록이 안 남아 "오늘의 승자"가 애매하고, 여러 판에 걸친 순위 경쟁이 성립하지 않는다.
3. 족보를 잘 모르는 초심자가 있으면 판이 멈춘다. 특히 섯다 특수패, 고스톱 점수 계산.
4. 판 진행자가 종이에 적으면 느리고, 분쟁이 나면 근거가 없다.

## Goals

**최우선 제약: 실물 게임을 방해하지 않는다.** 칩은 실물로 계속 쓰고, 앱은 판 옆에서 기록만 한다.

주 기능 (이것 때문에 앱을 쓴다):

- 방(room) 단위로 판별 승자·팟을 기록하고, 세션 결과와 누적 랭킹을 자동 집계한다.
- 섯다 끗·고스톱 점수·포커 족보를 카드 수동 선택(포커는 사진 인식 미지원) 또는 사진 한 장으로
  즉시 판독한다(족보 Advisor). 판정과 함께 서열 순위·승률·등장 확률 같은 통계도 보여준다.

보조 기능 (실물 칩이 부족하거나 디지털로 처리해야 할 때 꺼내 쓴다):

- 참가자별 바이인(가상 칩)과 잔액·순손익 추적.
- 원격 베팅 — `check`/`call`/`raise`/`fold`/`allin` 액션을 폰으로 입력. 방 생성 시 정한 입력 모드에 따라
  즉시 반영(신뢰 모드) 또는 딜러 승인 후 반영(승인 모드)한다.
- 실시간 화면 동기화 — 방 참가자 전원 화면이 같은 상태를 본다. 방은 동시에 여러 개 열려 있을 수 있다.

## Non-goals

- **실제 금전 거래·정산·환전 없음.** 모든 수치는 가상 칩이다. 결제 연동 없음.
- 카드 딜링·셔플 등 **게임 자체를 앱에서 플레이하지 않는다.** 실물 화투로 치고, 앱은 기록·보조만 한다.
- 봇·AI 상대 플레이 없음.
- 섯다·고스톱·포커 외 게임(바둑이 등)은 범위 밖.
- 공개 서비스·다중 테넌시 운영 없음. 지인 그룹 규모(방당 최대 10명)를 전제한다.
- 사이드팟 분배 없음. 판 종료 시 팟은 지정된 승자 한 명에게 전액 귀속된다.
- 족보 Advisor 판독 결과는 저장하지 않는다(`hand_records` 미구현). 화면을 벗어나면 사라진다.

## User Flow

```
[로그인] Authentik OIDC(운영) 또는 게스트 이름 로그인(AUTH_DEV_LOGIN=true, 개발용)
    ↓
[홈] 방 코드 입력해 입장 / 새 방 만들기 / 진행 중인 내 방 목록 / 족보 Advisor / 누적 랭킹
    ↓
[방 생성] 이름·게임 종류(섯다/고스톱/포커)·시작 칩·입력 모드(신뢰/승인) 지정 → 6자 코드 발급, host로 자동 입장
    ↓
[참가자] 코드로 입장 → 시작 칩만큼 자동 바이인 → 대기(waiting)
    ↓
[판 시작] host/dealer가 판을 연다(room.status → playing) → 실물로 화투를 친다
    ↓
[베팅]  참가자가 폰에서 액션 입력 (본인 또는, 딜러라면 대리 입력)
         ├─ 신뢰 모드 또는 딜러 자신의 입력: 즉시 확정, 칩 잔액 즉시 차감
         └─ 승인 모드의 player 입력: pending → 딜러/host가 승인·거절(사유 필수)
    ↓
[족보]  헷갈리면 족보 Advisor에서 카드 수동 선택 또는 사진 인식으로 끗/점수 확인 (방과 무관한 독립 화면)
    ↓
[판 종료] host/dealer가 승자 지정 → 팟이 승자에게 귀속, 판 기록 확정
         또는 판 무효화(재경기) → 그 판의 베팅 전액을 정정 행으로 환불
    ↓
[세션 정산] host가 방을 닫으면(closeRoom) room.status → settled → 세션 결과 화면(순손익·MVP·판 기록)
         ↓
[누적 랭킹] 정산 완료된 모든 세션을 합산한 순위표
```

## Requirements

관측 가능한 동작 기준으로 기술한다. 코드 근거는 각 항목에 표기.

### R1. 방 / 세션

- R1.1 로그인한 사용자는 방 이름, 게임 종류(`seotda`/`gostop`/`poker`), 시작 칩(1~1,000,000), 입력 모드(`trust`/`approval`)를
  지정해 방을 만든다. 생성자는 자동으로 `host` 역할과 시작 칩 바이인을 받는다.
  (`src/features/game/actions.ts` `createRoom`)
- R1.2 방 코드는 혼동 문자(0/O, 1/I/L)를 뺀 대문자·숫자 6자다. QR 발급 기능은 없다 — 코드 문자열만 공유한다.
  (`src/features/game/room-code.ts`)
- R1.3 방 역할은 `host`/`dealer`/`player`/`observer` 4종. `host`는 방 생성자 고정이며 재위임 불가.
  host는 다른 참가자의 역할을 바꿀 수 있다(`setMemberRole`). host/dealer만 판 시작·종료·무효화,
  베팅 승인·거절·정정을 할 수 있다. `observer`는 베팅할 수 없다.
  (`src/features/game/actions.ts`, `src/features/betting/actions.ts`)
- R1.4 방 정원은 최대 10명(좌석 0~9). 정산(`settled`)·종료(`closed`) 방은 신규 입장을 거부한다.
  이미 참가 중인 사용자의 재입장은 멱등(같은 코드로 다시 들어와도 에러 없이 통과).
  (`joinRoom`)
- R1.5 방 상태는 `waiting` → `playing` → `settled`/`closed` 로 서버가 단일 진실을 가진다.
  참가자는 `refreshRoom`으로 전체 스냅샷(`RoomSnapshot`)을 다시 받아 재접속 시 상태를 복원한다.
  (`src/features/game/types.ts`, `getRoomSnapshot`)
- R1.6 한 방에는 동시에 진행 중(`playing`) 판이 하나만 존재한다. 새 판 시작은 host/dealer만,
  이전 판이 끝나거나 무효화된 뒤에만 가능하다. (`startRound`)
- R1.7 판 종료는 승자 한 명을 지정하며, 그 시점 팟 전액이 승자 칩 잔액에 더해진다. 승인 대기(`pending`) 베팅이
  남아 있으면 판을 종료할 수 없다. (`endRound`)
- R1.8 판 무효화(재경기)는 그 판에서 나간 베팅 전부를 반대 부호 정정 행으로 환불하고, 판을 `voided`로 남긴다.
  (`voidRound`)

### R2. 실시간 동기화

- R2.1 베팅·라운드 이벤트는 Supabase Realtime **Broadcast** 공개 채널(`room:{uuid}`)로 행동한 클라이언트가
  Server Action 성공 후 직접 보낸다. 진실은 항상 서버 스냅샷이며, 수신 측은 이벤트를 리페치 트리거로만 쓴다
  (250ms 디바운스 + 20초 폴링 + 탭 전환 시 재조회). 상세 프로토콜은 `03-realtime-protocol.md` 소유.
- R2.2 동일 베팅 요청이 중복 전송돼도 상태가 깨지지 않는다 — 베팅 액션 ID는 클라이언트 생성 UUID이자
  DB PK이며 재전송 시 기존 행을 그대로 반환한다(멱등). (`placeBet`)

### R3. 예산 / 베팅

- R3.1 참가자는 방 입장 시 방의 시작 칩만큼 자동 바이인을 받는다. 추가 바이인은 본인이 언제든,
  또는 딜러/host가 다른 참가자를 대신해 추가할 수 있다. 정산·종료된 방에는 바이인을 추가할 수 없다.
  (`src/features/budget/actions.ts` `addBuyIn`)
- R3.2 베팅 액션은 `check`/`call`/`raise`/`fold`/`allin`. `call`/`raise`/`allin`은 금액(1 이상)이 필요하다.
- R3.3 잔액보다 큰 금액의 베팅은 요청 시점에 거부된다. 승인 대기 중 잔액이 줄어 있으면 승인 시점에
  자동 거절되고 사유가 남는다. (`placeBet`, `approveBet`)
- R3.4 승인 모드에서 player의 베팅은 `pending`으로 남아 host/dealer 승인 전까지 칩이 움직이지 않는다.
  거절은 사유가 필수다. 신뢰 모드이거나 딜러 본인/대리 입력이면 즉시 `accepted`.
- R3.5 딜러/host는 다른 참가자를 대신해 베팅을 입력할 수 있다(`targetUserId`). observer는 대상이 될 수 없다.
- R3.6 확정된(`accepted`) 베팅은 진행 중인 판에 한해 host/dealer가 정정할 수 있다. 원장 행을 고치지 않고
  반대 부호 정정 행을 추가한다(`chip_ledger` append-only, `revertedOf`로 원행 참조). 끝난 판은 판 무효화로만
  되돌린다. (`revertBet`)
- R3.7 잔액이 특정 한도 이하로 떨어질 때 사전 경고를 띄우는 기능은 없다 — 부족은 베팅 시도 시점에만 차단된다.

### R4. 랭킹 / 기록

- R4.1 세션 결과 화면(`/rooms/{code}/result`)은 방 참가자별 승수, 바이인 합계, 잔액, 순손익과
  전체 판 기록(승자·팟·비고, 무효 판은 "재경기"로 표기)을 보여준다. MVP(순손익 1위, net > 0일 때만),
  한방(최대 팟), 불도저(최다 레이즈), 여우(최다 다이) 배지를 계산한다. (`src/features/ranking/queries.ts`)
- R4.2 누적 랭킹(`/ranking`)은 **정산 완료(settled/closed)된 세션만** 합산해 사용자별 세션 수·승수·순손익
  합계를 보여준다. 집계 범위는 전역 사용자 단위다(그룹 단위 분리는 미구현 — Open Questions 참조).
  (`getCumulativeRanking`)

### R5. 족보 Advisor

- R5.1 `/advisor`는 방과 무관한 독립 화면이며 섯다/고스톱/포커 탭 3개가 있다. 섯다↔고스톱처럼
  화투 탭끼리 전환하면 카드 선택이 초기화된다. 포커 선택은 별도 state라 화투 탭을 오가도
  유지된다. 섯다는 카드 2장까지, 고스톱은 30장까지, 포커는 7장까지 선택할 수 있다. 선택 즉시
  판정(끗/점수/족보)과 통계가 표시된다. (`src/features/jokbo-advisor/components/advisor-client.tsx`)
- R5.2 섯다는 서열 순위(전체 단계 중 N위)·동급 조합 수·상대 1명 기준 승률(남은 18장에서 상대가
  받을 수 있는 153가지 조합 전수 대조)을 보여준다. 포커는 족보 순위(10개 중 N위)와 5장 무작위
  기준 등장 확률(표준 포커 확률표)을 보여준다. (`src/features/jokbo-advisor/stats.ts`)
- R5.3 `JOKBO_VISION_ENABLED=true` 이고 `ANTHROPIC_API_KEY`가 설정된 경우에만 사진 인식(`recognizeHand`)이
  노출된다. 미설정이면 수동 카드 피커만 보인다. 사진 인식은 섯다·고스톱에만 있다 — 포커 탭에는
  업로드 버튼 자체가 렌더되지 않는다. (`src/app/advisor/page.tsx`)
- R5.4 인식 결과는 선택 목록에 반영될 뿐이며, 사용자가 이후 자유롭게 추가·해제할 수 있다.
- R5.5 판독 결과는 **저장되지 않는다.** 화면을 벗어나거나 새로고침하면 사라진다. 다른 참가자에게 공유되지 않는다.

### R6. 게임 가이드

- R6.1 `/guide`는 로그인이 필요한 정적 정보 페이지다(방과 무관). 섯다·고스톱·포커 족보
  서열표와 앱 사용법(`/guide/usage`)을 별도 하위 라우트로 제공한다.
  (`src/app/guide/page.tsx`, `guide/seotda`, `guide/gostop`, `guide/poker`, `guide/usage`)
- R6.2 서열표는 예시 카드를 실제 카드 비주얼(`HwatuCardView`/포커 카드 칩)로 렌더링한다.
  서열 순서 자체가 각 게임 엔진의 카테고리 우선순위와 일치해야 한다는 것이 계약이다.

## Acceptance Criteria

- [ ] 2대 이상 기기에서 같은 방에 입장 후, 한쪽 베팅이 다른 쪽 화면에 반영된다(브로드캐스트 힌트 + 스냅샷 리페치).
- [ ] 앱을 강제 종료 후 재입장하면 `refreshRoom` 스냅샷으로 칩 잔액·진행 중 판 상태가 정확히 복원된다.
- [ ] 섯다 20장 조합 전수(190가지)에 대해 엔진 판정이 규칙표와 일치한다 (단위 테스트, `04-game-engines.md` 소유).
- [ ] 고스톱 대표 점수 시나리오가 규칙표와 일치한다 (단위 테스트, `04-game-engines.md` 소유).
- [ ] 포커 5~7장 대표 시나리오(백스트레이트 포함)에서 최선 5장 평가와 서열이 표준 족보표와
  일치한다 (단위 테스트, `04-game-engines.md` 소유).
- [ ] 판 종료 시 팟 전액이 지정된 승자 잔액에 정확히 반영된다(`chip_ledger` 합산 검증).
- [ ] 방 참가자가 아닌 사용자는 그 방의 어떤 데이터도 조회할 수 없다 — Server Action의 멤버십 검사와
  RLS 양쪽으로 확인한다(`07-auth-and-security.md`).
- [ ] 사진 인식이 비활성이거나 실패해도 수동 카드 선택만으로 끗/점수 확인이 100% 가능하다.
- [ ] 11번째 참가자의 방 입장은 거부된다("방이 가득 찼습니다").
- [ ] 승인 대기 베팅이 남아 있으면 판 종료 요청이 거부된다.

## Edge Cases

| 상황 | 기대 동작 |
|------|-----------|
| host가 방을 떠나거나 접속 끊김 | host 역할은 재위임되지 않는다 — 다른 host 지정 기능 없음. dealer 위임(`setMemberRole`)으로 진행은 대체 가능 |
| 승인 대기 중 대상자 잔액이 줄어듦(다른 베팅 승인 등) | 승인 시점에 자동 거절 + 사유 "잔액 부족 (자동 거절)" |
| 판 진행 중 참가자 추가 입장 | 즉시 `player`로 합류하고 다음 판부터 베팅 가능. 진행 중 판의 액션 이력은 그대로 보인다 |
| 같은 코드로 이미 참가 중인 사용자가 재입장 | 에러 없이 기존 멤버십 반환(멱등) |
| 승인 대기 베팅을 남긴 채 판 종료 시도 | 거부 — "승인 대기 중인 베팅을 먼저 처리하세요" |
| 정산(settled)된 방에 추가 바이인 시도 | 거부 |
| 사진에 카드가 부분적으로 가려짐 | 인식 신뢰도 표시 + 수동 확인 요구 (`05-jokbo-advisor.md` 소유) |
| 같은 클라이언트 베팅 요청이 네트워크 재시도로 중복 전송 | actionId 멱등으로 기존 행 반환, 중복 차감 없음 |

## Dependencies

- Supabase 프로젝트 (Postgres + Realtime Broadcast) — `01-architecture.md`
- Authentik OIDC 애플리케이션 등록(`AUTH_AUTHENTIK_*` 3종) 또는 개발 게스트 로그인(`AUTH_DEV_LOGIN=true`) — `07-auth-and-security.md`
- Anthropic API 키(`ANTHROPIC_API_KEY`) + `JOKBO_VISION_ENABLED=true` — 미설정 시 vision 없이 수동 피커만 동작 — `05-jokbo-advisor.md`
