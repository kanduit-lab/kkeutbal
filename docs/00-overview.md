## Problem

MT·모임에서 친구들끼리 **돈을 걸지 않고** 화투(섯다·고스톱)를 할 때:

1. 칩을 공용으로 쓰기 때문에 누가 얼마를 땄는지 판이 끝나면 알 수 없다.
2. 승패 기록이 안 남아 "오늘의 승자"가 애매하고, 여러 판에 걸친 순위 경쟁이 성립하지 않는다.
3. 개인이 얼마나 썼는지(가상 예산) 추적이 안 돼 판이 과열되거나 흐지부지된다.
4. 족보를 잘 모르는 초심자가 있으면 판이 멈춘다. 특히 섯다 특수패, 고스톱 점수 계산.
5. 판 진행자가 종이에 적으면 느리고, 분쟁이 나면 근거가 없다.

## Goals

- 방(room) 단위로 **모든 베팅·결과를 실시간 기록**하고, 참가자 전원 화면이 즉시 동기화된다.
- 참가자별 **가상 예산/바이인**과 순손익을 자동 계산한다.
- 세션 및 누적 기준 **승패 랭킹**을 제공한다.
- 섯다 끗·고스톱 점수를 **수동 입력 또는 사진 한 장으로 즉시 판독**한다.
- 입력 부담을 한 명(딜러/감사)에게 몰지 않고 **플레이어 분산 입력 + 승인**도 가능하게 한다.
- 실물 게임 속도를 방해하지 않는다 — 한 액션 입력이 **3초 이내, 탭 2회 이내**.

## Non-goals

- **실제 금전 거래·정산·환전 없음.** 모든 수치는 가상 칩/점수다. 결제 연동 없음.
- 카드 딜링·셔플 등 **게임 자체를 앱에서 플레이하지 않는다.** 실물 화투로 치고, 앱은 기록·보조만 한다.
- 봇·AI 상대 플레이 없음.
- 섯다·고스톱 외 게임(포커·바둑이 등)은 초기 범위 밖. 엔진은 플러그인 구조로 열어둔다.
- 공개 서비스·다중 테넌시 운영 없음. 지인 그룹 규모(방당 2~10명)를 전제한다.

## User Flow

```
[방장] 로그인(Authentik SSO) → 방 생성(게임 선택, 시작 칩, 규칙) → 방 코드/QR 공유
        ↓
[참가자] 로그인 → 코드/QR 입장 → 바이인 확정 → 대기
        ↓
[판 시작] 실물로 화투를 친다
        ↓
[베팅]  각자 폰에서 액션 입력(콜/레이즈/다이/판돈)
         ├─ 신뢰 모드: 즉시 반영
         └─ 승인 모드: 딜러가 승인해야 반영
        ↓
[족보]  헷갈리면 족보 Advisor — 카드 수동 선택 or 사진 촬영 → 끗/점수 즉시 표시
        ↓
[판 종료] 승자·팟 확정 → 참가자 칩 잔액 자동 갱신 → 판 로그 적재
        ↓
[세션 종료] 순손익 정산 화면 → 랭킹·MVP·통계 → 누적 전적 반영
```

## Requirements

관측 가능한 동작 기준으로 기술한다. 상세 스펙은 각 소유 문서 참조.

### R1. 방 / 세션

- R1.1 로그인한 사용자는 게임 종류(섯다·고스톱), 시작 칩, 입력 모드를 지정해 방을 만들 수 있다.
- R1.2 방은 6자리 코드와 QR을 가진다. 코드로 입장한 사용자는 참가자가 된다.
- R1.3 방에는 `host`, `dealer`, `player`, `observer` 역할이 있다. 역할별 권한은 `07-auth-and-security.md`가 소유한다.
- R1.4 방 상태(`waiting` / `playing` / `settled` / `closed`)는 서버가 단일 진실이며 전원에게 브로드캐스트된다.
- R1.5 접속이 끊긴 참가자가 재입장하면 현재 방 상태를 전량 복원 받는다.

### R2. 실시간 동기화

- R2.1 베팅·라운드 이벤트는 발생 후 **p95 300ms 이내**에 다른 참가자 화면에 반영된다.
- R2.2 모든 실시간 payload는 스키마 검증을 통과해야 하며, 실패 시 무시하고 경고를 남긴다.
- R2.3 동일 이벤트가 중복 수신돼도 상태가 깨지지 않는다(멱등).
- R2.4 프로토콜·채널 구조는 `03-realtime-protocol.md`가 소유한다.

### R3. 예산 / 베팅

- R3.1 참가자는 세션 시작 시 바이인(가상 칩)을 정하고, 추가 바이인은 기록으로 남는다.
- R3.2 잔액이 설정 한도 이하로 떨어지면 본인과 딜러에게 경고가 표시된다.
- R3.3 베팅 액션은 `check` `call` `raise` `fold` `allin` 및 자유 금액 입력을 지원한다.
- R3.4 승인 모드에서는 딜러 승인 전까지 액션이 `pending`이며, 거절 시 사유가 남는다.
- R3.5 모든 칩 이동은 되돌릴 수 있고, 되돌린 기록도 로그에 남는다(정정 이력 보존).
- R3.6 상세는 `06-features-ranking-budget-betting.md`가 소유한다.

### R4. 랭킹 / 기록

- R4.1 판 단위 로그에서 참가자별 순손익·승수·참여 판수가 자동 집계된다.
- R4.2 세션 랭킹과 누적(전체 기간) 랭킹을 각각 조회할 수 있다.
- R4.3 승률, 최대 획득 팟, 최다 연승, 최다 다이 등 재미 지표를 제공한다.

### R5. 족보 Advisor

- R5.1 사용자는 화투 카드를 수동 선택해 섯다 끗/족보 또는 고스톱 점수를 즉시 확인할 수 있다.
- R5.2 사용자는 카드 사진을 촬영/업로드해 카드 인식 결과를 받을 수 있다.
- R5.3 인식 결과는 **항상 수정 가능**하다. 인식은 보조이며 최종 확정은 사람이 한다.
- R5.4 내 손패 판독 결과는 기본적으로 **나에게만** 보인다.
- R5.5 상세는 `04-game-engines.md`(규칙)와 `05-jokbo-advisor.md`(입력·인식)가 소유한다.

## Acceptance Criteria

- [ ] 2대 이상 기기에서 같은 방에 입장 후, 한쪽 베팅이 다른 쪽에 300ms 내 반영된다.
- [ ] 앱을 강제 종료 후 재입장하면 칩 잔액·현재 판 상태가 정확히 복원된다.
- [ ] 섯다 20장 조합 전수(190가지)에 대해 엔진 판정이 규칙표와 일치한다 (단위 테스트).
- [ ] 고스톱 대표 점수 시나리오(광·띠·끗·피·고·흔들기·피박·광박)가 규칙표와 일치한다 (단위 테스트).
- [ ] 세션 종료 시 전 참가자 순손익 합계가 0이다 (칩 보존 불변식).
- [ ] 방 참가자가 아닌 사용자는 그 방의 어떤 데이터도 조회할 수 없다 (RLS 검증).
- [ ] 사진 인식 실패 시에도 수동 입력으로 100% 대체 가능하다.

## Edge Cases

| 상황 | 기대 동작 |
|------|-----------|
| 딜러가 이탈 | host가 다른 참가자에게 dealer 역할 재위임 |
| 두 명이 동시에 같은 판 결과 입력 | 서버가 라운드 시퀀스로 하나만 수용, 나머지는 충돌 안내 |
| 오프라인 상태에서 액션 입력 | 로컬 큐에 적재, 재연결 시 순서대로 재전송(멱등키 사용) |
| 판 도중 참가자 추가 입장 | 다음 판부터 참여. 진행 중 판에는 관전자 |
| 칩 잔액 음수 | 허용하지 않음. 추가 바이인 유도 |
| 사진에 카드가 부분적으로 가려짐 | 인식 신뢰도 표시 + 수동 확인 요구 |
| 같은 사용자가 두 기기로 접속 | 최신 세션 우선, 이전 세션은 읽기 전용 안내 |
