## Problem

공용 칩을 쓰면 개인 손익이 사라진다. 종이에 적으면 느리고 근거가 남지 않는다.
동시에, 한 사람이 전부 입력하면 그 사람만 게임을 못 한다.

## 1. 원격 베팅

### 입력 모드 — 방 생성 시 선택

| 모드 | 동작 | 적합한 상황 |
|------|------|-------------|
| `trust` (신뢰) | 각자 입력 즉시 반영 | 서로 믿는 친구 사이. 기본값 |
| `approval` (승인) | 딜러가 승인해야 반영 | 인원이 많거나 판이 큰 경우 |

**두 모드를 다 만드는 이유**: 신뢰 모드는 빠르지만 오입력이 그대로 남고, 승인 모드는 정확하지만
딜러가 병목이 된다. 상황이 다르므로 하나로 고를 수 없다. 방 단위로 정하고 진행 중 전환 가능하다.

한 명이 전담하는 "감사 모드"는 별도 모드가 아니라 **`approval` + 딜러가 대리 입력**으로 표현된다.
딜러는 다른 참가자를 대신해 액션을 넣을 수 있고, 그 기록에는 대리 입력자가 남는다.

### 액션

`check` · `call` · `raise` · `fold` · `allin` + 자유 금액.
금액은 **정수 칩**만 허용한다 (부동소수 반올림 오차 차단, `02-data-model.md`).

### 상태 전이

```
[제출] pending ──승인──► accepted ──정정──► reverted
          │                  │
          └──거절──► rejected └──(칩 원장 기록)
```

- `trust` 모드에서는 `pending`을 건너뛰고 바로 `accepted`.
- `rejected`는 사유를 필수로 남긴다. 사유 없는 거절은 분쟁을 만든다.
- `reverted`는 원본 행을 수정하지 않고 원장에 반대 부호 행을 추가한다. 원본 기록은 보존된다.

### 요구사항

- B1. 액션 제출은 **탭 2회 이내, 3초 이내**에 끝난다.
- B2. 제출한 액션은 발신자 화면에 즉시 반영되고(낙관적), 서버 확정 시 정합된다.
- B3. 승인 대기 액션은 딜러 화면 상단에 모여 한 번에 처리할 수 있다.
- B4. 모든 액션은 되돌릴 수 있고, 되돌린 이력도 조회 가능하다.
- B5. 잔액을 초과하는 베팅은 제출 자체가 막힌다 (`allin`으로 유도).

## 2. 개인 예산

### 개념

- **바이인(buy-in)**: 세션 시작 시 각자 가져오는 가상 칩. 추가 바이인은 별도 기록.
- **잔액(balance)**: `SUM(chip_ledger.delta)`. 저장 컬럼이 아니라 도출값이다.
- **순손익(net)**: `잔액 − 총 바이인`. 랭킹의 기준 값.

### 요구사항

- U1. 참가자는 입장 시 바이인을 확정한다. 방 기본값을 제시하되 개별 조정 가능.
- U2. 추가 바이인은 언제든 가능하나 **기록으로 남고 순손익에 반영**된다.
  기록 없는 추가 칩은 랭킹을 무의미하게 만든다.
- U3. 잔액이 경고 임계값(기본: 바이인의 20%) 이하가 되면 본인과 딜러에게 표시된다.
- U4. 잔액은 음수가 될 수 없다.
- U5. 세션 종료 시 전 참가자 순손익 합계는 **정확히 0**이다 (칩 보존 불변식).

U5는 단순 검증이 아니라 **버그 탐지기**다. 합이 0이 아니면 어딘가 칩이 생기거나 사라진 것이므로
정산 화면에서 경고를 띄우고 원장 감사 링크를 제공한다.

## 3. 랭킹 · 기록

### 범위

| 범위 | 대상 | 의미 |
|------|------|------|
| 세션 (room) | 그 방 참가자 | 오늘 판의 승자 |
| 누적 (group) | 친구 그룹 | 장기 전적 |

전역 랭킹은 만들지 않는다 — 지인 밖 비교는 의미가 없고 노출 범위만 넓힌다 (`02-data-model.md`).

### 지표 정의

이 표가 지표 정의의 소유자다. 다른 문서·코드는 여기 정의를 따른다.

| 지표 | 정의 |
|------|------|
| 순손익 | `현재 잔액 − 총 바이인` |
| 참여 판수 | 해당 방에서 `fold` 포함 액션이 1건 이상인 `round` 수 |
| 승수 | `rounds.winner_id` 가 본인인 판 수 |
| 승률 | `승수 / 참여 판수`. 참여 판수 0이면 미표시(0% 아님) |
| 최대 획득 팟 | 승리한 판의 `pot` 최댓값 |
| 최다 연승 | 참여 판 순서 기준 연속 승리 최대 길이 |
| 다이율 | `fold 액션 수 / 참여 판수` |
| 평균 베팅 | `accepted` 액션의 `amount` 평균 (0 금액 제외) |

### 재미 지표 (표시 전용)

랭킹 표 아래 배지로 노출한다. 순위 계산에는 넣지 않는다.

- **MVP** — 순손익 1위
- **호구** — 순손익 최하위
- **불도저** — 평균 베팅 최고
- **여우** — 다이율 최고인데 순손익 양수
- **한방** — 최대 획득 팟 보유자

승패만 남기면 재미가 없고, 순위 계산에 섞으면 순위가 애매해진다. 그래서 분리한다.

### 요구사항

- R1. 세션 종료 즉시 랭킹이 확정되고 공유 가능한 결과 화면이 뜬다.
- R2. 누적 랭킹은 그룹 단위로 조회되며, 참여 판수가 일정 수 미만인 사용자는 별도 표기한다
  (적은 표본의 승률 왜곡 방지).
- R3. 모든 지표는 원장(`chip_ledger`)과 판 기록에서 도출된다. 별도 집계 테이블을 두지 않는다.

## Acceptance Criteria

- [ ] 승인 모드에서 딜러가 거절하면 제출자 화면에서 액션이 롤백되고 사유가 표시된다.
- [ ] 액션을 되돌린 뒤에도 원본 액션과 정정 기록이 모두 조회된다.
- [ ] 잔액 초과 베팅이 UI에서 제출 불가하고, 서버에서도 거부된다 (이중 방어).
- [ ] 세션 정산 화면에서 순손익 합계 0이 검증되고, 불일치 시 경고가 뜬다.
- [ ] 참여 판수 0인 사용자의 승률이 `0%`가 아니라 `-`로 표시된다.

## Edge Cases

| 상황 | 기대 동작 |
|------|-----------|
| 판 도중 참가자 이탈 | 해당 판까지의 액션은 유효. 이후 판 미참여로 집계 |
| 딜러가 자기 액션을 승인 | 허용하되 로그에 자가승인으로 표기 |
| 추가 바이인 후 즉시 이탈 | 바이인 기록 유지, 순손익에 반영 |
| 같은 판에 승자 두 번 입력 | `rounds.seq` 기준으로 후속 입력 거부, 정정은 revert 경로로 |
| 정산 후 오류 발견 | 방을 `settled`에서 되돌리지 않고 정정 원장 추가로 처리 |
