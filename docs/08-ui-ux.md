## 사용 맥락이 설계를 결정한다

이 앱은 책상 앞이 아니라 **판 옆에서** 쓰인다. 그래서 전제가 다르다.

| 맥락 | 설계 결론 |
|------|-----------|
| 한 손은 화투를 쥐고 있다 | 한 손 엄지 조작. 주요 액션은 화면 하단 |
| 조명이 어둡다 (펜션·밤) | 고대비 다크 우선. 얇은 회색 텍스트 금지 |
| 시끄럽고 산만하다 | 텍스트보다 숫자·색으로 상태 전달. 읽어야 알 수 있는 UI 지양 |
| 내 차례는 몇 초뿐 | 액션 **탭 2회·3초 이내**. 확인 단계 최소화 |
| 화면을 남이 본다 | 내 손패는 기본 가림. 명시적 조작으로만 노출 |

## 화면 구성

```
/                     홈 — 진행 중인 방, 코드 입장, 최근 전적
/login                Authentik SSO 진입
/rooms/new            방 생성 (게임·시작칩·입력모드·룰)
/rooms/[code]         방 대기실 — 참가자·바이인·역할
/rooms/[code]/play    판 진행 (핵심 화면)
/rooms/[code]/ledger  칩 원장 · 감사 로그
/rooms/[code]/result  세션 정산 결과
/ranking              누적 랭킹 (그룹)
/advisor              족보 Advisor 단독 진입 (방 밖에서도 사용 가능)
```

`/advisor`를 방 밖에서도 열 수 있게 하는 이유: 앱을 처음 쓰는 사람이 방에 들어오기 전에
족보를 확인해볼 수 있어야 진입 장벽이 낮아진다.

## 판 진행 화면 (핵심)

```
┌──────────────────────────────────┐
│ 방이름  4판째        팟 12,500   │  ← 상단 고정. 판 번호·팟만
├──────────────────────────────────┤
│  ┌────────┐ ┌────────┐           │
│  │ 민수   │ │ 지훈   │           │  ← 참가자 타일
│  │ 32,000 │ │  8,200 │           │     칩 · 상태(대기/콜/다이)
│  │  콜    │ │  다이  │           │     접속 여부는 테두리로
│  └────────┘ └────────┘           │
│  ┌────────┐ ┌────────┐           │
│  │ 나     │ │ 은지   │           │
│  │ 21,500 │ │ 15,000 │           │
│  └────────┘ └────────┘           │
├──────────────────────────────────┤
│         [ 족보 보기 ]             │  ← Advisor 시트 열기
├──────────────────────────────────┤
│  [다이]  [콜]  [레이즈]  [올인]   │  ← 엄지 영역. 최소 56px 높이
└──────────────────────────────────┘
```

- 참가자 타일은 **개수가 변해도 위치가 흔들리지 않게** 고정 그리드로 배치한다.
- 실시간 갱신이 잦으므로 숫자 변경은 자리 이동 없이 값만 바뀐다 (레이아웃 안정성).
- 접속 끊긴 참가자는 타일을 지우지 않고 흐리게 표시한다. 사라지면 오해가 생긴다.

### 액션 입력

- 탭 1: 액션 버튼 → 탭 2: 금액 확정(레이즈만). 나머지는 1탭.
- 레이즈 금액은 프리셋 칩(+1k/+5k/×2/올인)으로 제시한다. 숫자 키패드는 마지막 수단.
- 제출 즉시 낙관적 반영 + **대기 표시(pending)**. 서버 확정 시 표시가 사라진다.
- 서버가 거절하면 롤백하고 **사유를 인라인으로** 보여준다 — 토스트로만 처리하지 않는다
  (권한·검증 실패는 설명이 필요한 실패다).

### 딜러 화면 추가 요소

승인 모드일 때 상단에 **대기열 스택**이 붙는다. 한 번에 훑고 일괄 승인할 수 있어야 딜러가
병목이 되지 않는다. 거절은 사유 입력을 강제한다.

## 족보 Advisor

바텀시트로 연다. 판 화면을 떠나지 않는 것이 핵심이다.

```
┌──────────────────────────────────┐
│  판정 결과: 독사                  │  ← 즉시 갱신. 선택하는 동안 계속 보임
│  (1월 · 4월)                      │
├──────────────────────────────────┤
│  [사진으로 인식]                  │  ← vision 비활성 시 이 버튼 자체가 없음
├──────────────────────────────────┤
│   1월  2월  3월  4월  5월         │  ← 카드 그리드
│   6월  7월  8월  9월 10월         │     섯다면 11·12월 비활성
└──────────────────────────────────┘
```

- 결과는 **선택 즉시** 갱신된다. 확정 버튼을 기다리게 하지 않는다.
- 인식 결과는 프리필일 뿐이며 언제나 수정 가능하다. 저신뢰 카드는 색으로 구분한다
  (`05-jokbo-advisor.md` 신뢰도 표).
- 시트를 닫으면 결과는 화면에서 사라진다. 남의 눈에 오래 띄지 않게 하는 것이 기본값이다.

## 상태 처리

모든 데이터 화면은 로딩·빈 상태·에러·성공을 각각 다르게 다룬다. 하나의 문구로 뭉뚱그리지 않는다.

| 상황 | 처리 |
|------|------|
| 로딩 | 스켈레톤. 레이아웃 크기를 미리 잡아 화면이 튀지 않게 한다 |
| 방 없음 | "이 코드의 방이 없습니다" + 코드 다시 입력 경로 |
| 방 종료됨 | "이미 끝난 방입니다" + 결과 화면 링크 (없음과 구분) |
| 권한 없음 | 거부 표면 — 무엇이 막혔는지 설명 + 필요한 역할을 별도 태그로 |
| 네트워크 끊김 | 상단 배너 상시 표시 + 재연결 시도 중 표기. 액션은 로컬 큐에 쌓임 |
| 판 없음(대기실) | "아직 시작한 판이 없습니다" + 딜러면 시작 버튼, 아니면 안내 |
| 서버 에러 | 재시도 버튼 제공. 내부 ID·스택 노출 금지 |

**404와 권한 거부를 같은 화면으로 처리하지 않는다.** 방이 없는 것과 못 들어가는 것은 다른 문제고
사용자가 취할 행동도 다르다.

### 토스트 vs 다이얼로그

| 토스트 (짧고 비차단) | 다이얼로그 (결과 설명 필요) |
|---|---|
| 방 코드 복사됨 | 방 종료 · 정산 확정 |
| 액션 제출됨 | 액션 정정(revert) |
| 승인 완료 | 역할 위임 |
| 재연결됨 | 참가자 강퇴 |

- 같은 액션에 토스트가 중복으로 뜨지 않게 한다.
- 다이얼로그 버튼은 `확인`이 아니라 **`정산 확정`, `방 종료`처럼 행동을 이름으로** 쓴다.
- 되돌리기 어려운 액션은 결과와 범위를 본문에 쓴다. "이 판의 칩 이동이 원장에 정정으로 남습니다."

## 권한 게이팅

역할별 노출은 3단계로 나눈다.

| 단계 | 대상 | 예시 |
|------|------|------|
| 숨김 | 알 필요 없는 관리 기능 | 방 설정 변경, 룰 편집 (host 아닌 사람에게) |
| 비활성 + 툴팁 | 상태를 알려주는 게 유용한 액션 | 판 시작/종료, 승인·거절, 정정 (player에게 비활성 + 이유 표기) |
| 거부 표면 | 페이지 전체가 막힌 경우 | 참가하지 않은 방 URL 직접 접근 |

버튼을 숨기는 것은 **편의이지 보안이 아니다.** 서버는 항상 다시 검증한다
(`07-auth-and-security.md`).

## 인터랙션 규칙

- **hover만으로 내용을 드러내지 않는다.** 모바일에서 hover는 존재하지 않는다.
  참가자 상세·오버플로 메뉴는 전부 클릭 토글 + 바깥 클릭 닫기.
- 여러 참가자 타일의 메뉴는 부모가 열림 상태를 가져 **한 번에 하나만** 열린다.
- 팝오버·툴팁이 주변 레이아웃을 밀지 않는다. 오버레이로 띄운다.
- 탭 타깃 최소 44×44px. 액션 바 버튼은 56px 이상.
- 실수로 누르기 쉬운 파괴적 액션(올인·방 종료)은 다른 버튼과 물리적으로 떨어뜨린다.

## 접근성 · 실사용

- 색만으로 상태를 전달하지 않는다. 색 + 아이콘 + 텍스트를 함께 쓴다 (다이/콜 구분).
- 폰트 크기는 시스템 설정을 따라 확대되어도 레이아웃이 깨지지 않아야 한다.
- 화면 꺼짐 방지를 판 진행 화면에서만 적용한다 (배터리).
- 세로 모드 우선. 가로 모드는 깨지지만 않으면 된다.

## 시각 변경 확인

눈에 보이는 UI 변경은 **커밋·푸시 전에 사용자 확인을 받는다.** 스크린샷이나 실행 화면으로
확인 후 진행한다. 이 규칙은 구현 단계에서 적용된다.
