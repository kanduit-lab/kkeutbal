## 사용 맥락이 설계를 결정한다

이 앱은 책상 앞이 아니라 **판 옆에서** 쓰인다.

| 맥락 | 설계 결론 |
|------|-----------|
| 한 손은 화투를 쥐고 있다 | 한 손 엄지 조작. 주요 액션은 화면 하단 고정 |
| 조명이 어둡다 (펜션·밤) | 다크 전용 (`globals.css`, 라이트 테마 없음). 얇은 회색 텍스트 금지 |
| 시끄럽고 산만하다 | 텍스트보다 숫자·색으로 상태 전달 |
| 화면을 남이 본다 | 딜러 전용 컨트롤은 role 기반으로 아예 렌더되지 않음 |

## 화면 구성

실제 라우트는 `src/app/` 기준 다음이 전부다. `loading.tsx`/`error.tsx`/`not-found.tsx` 같은
Next.js 특수 파일은 하나도 없다 — 로딩·에러 처리는 전부 컴포넌트 내부에서 수동으로 한다.

```
/                     홈 — 방 입장 코드 입력 · 내 활성 방 목록 · Advisor/랭킹 진입 (page.tsx)
/login                로그인 (login/page.tsx)
/rooms/new            방 생성 (rooms/new/page.tsx)
/rooms/[code]         방 화면 — 대기·진행·딜러 컨트롤이 한 화면 (rooms/[code]/page.tsx)
/rooms/[code]/result  세션 정산 결과 (rooms/[code]/result/page.tsx)
/ranking              누적 랭킹, 정산 완료 세션만 집계 (ranking/page.tsx)
/advisor              족보 Advisor 단독 페이지 (advisor/page.tsx)
```

기존 설계에 있던 `/rooms/[code]/play`, `/rooms/[code]/ledger`는 **존재하지 않는다.**
판 진행은 대기실과 분리된 별도 화면이 아니라 `/rooms/[code]` 한 화면에서 라운드 유무로
콘텐츠가 바뀐다. 칩 원장 감사 로그 전용 화면도 아직 없다 — `chip_ledger` 조회 UI는 미구현
(Open Questions 참고).

`/advisor`는 로그인만 요구하고 방 소속을 요구하지 않는다 (`advisor/page.tsx`). 방에 들어오기
전에도 족보를 확인해볼 수 있게 하는 진입 장벽 완화용 설계다.

## 홈 화면 (`/`)

`getMyActiveRooms`로 내 활성 방을 서버에서 조회해 카드 목록으로 보여준다. 항목이 없으면
`EmptyState`("진행 중인 방이 없습니다"). 방 코드 입력 폼(`joinRoomAndGo`)과 방 생성 링크,
Advisor/랭킹 진입 타일 2개가 전부다. `searchParams.error`가 있으면 상단에 인라인 에러 문구를
표시한다 — 토스트가 아니다 (마운트 시점에 토스트 컨텍스트가 아직 없는 서버 리다이렉트 경로라서).

## 방 화면 (`/rooms/[code]`) — 핵심

서버 컴포넌트(`rooms/[code]/page.tsx`)가 방을 찾고, 비멤버면 자동 입장을 시도하고, 스냅샷을
클라이언트 컴포넌트 `RoomClient`(`src/features/game/components/room-client.tsx`)에 넘긴다.
서버 단계에서 분기되는 화면 3가지:

| 조건 | 결과 |
|------|------|
| 코드에 해당하는 방 없음 | `ErrorScreen` "방을 찾을 수 없습니다" + 홈 버튼 |
| 방이 `settled`/`closed` | `/rooms/[code]/result`로 즉시 redirect (에러 화면 아님) |
| 비멤버 자동 입장 실패 (`joinRoom` 거부) | `ErrorScreen` "입장할 수 없습니다" + 서버 에러 메시지 |

방 없음과 방 종료됨은 서로 다른 결과로 분리되어 있다 — 종료된 방은 결과 화면으로 바로
넘어가고, 존재 자체가 없는 방만 에러 화면을 띄운다.

`RoomClient`는 라운드 유무나 역할과 무관하게 아래 구성 요소를 **전부 같은 화면에** 쌓는다.
바텀시트나 화면 전환이 아니다.

```
헤더: ← 홈 | 방이름 · 코드 · 게임종류 · 입력모드   [연결 끊김 배지] [N판 진행/대기 배지]
팟 표시: 현재 팟 금액 (라운드 없으면 지난 판 결과 한 줄)
참가자 그리드 (ParticipantGrid) — 2열 고정
이번 판 액션 로그 (RoundLog) — 최근 항목이 위, 최대 높이 스크롤
[딜러/방장이면] 딜러 컨트롤 패널 (DealerPanel)
[observer가 아니면] 하단 고정 액션 바 (ActionBar)
```

### 참가자 그리드 (`participant-grid.tsx`)

- 2열 grid, 멤버 배열 순서 그대로 — 인원 변화에도 개별 타일 위치는 안정적이다(추가/제거 시
  자연스레 뒤로 밀림, 애니메이션 없음).
- 접속 상태는 타일 테두리가 아니라 **이름 옆 작은 점**(녹색=온라인, 회색=오프라인)으로 표시한다.
  Presence sync 이벤트 기반. 접속 끊긴 멤버도 타일은 그대로 남는다 — 지우지 않는다.
- 본인 타일: `ring-1 ring-accent` + 이름 옆 "나" 라벨.
- 직전 라운드 승자(현재 라운드가 없을 때만): `ring-2 ring-win`.
- role 배지(방장/딜러/관전)는 `player`에는 표시하지 않는다(기본 역할이라 노이즈).
- 잔액이 0 이하면 숫자 색이 accent(경고색)로 바뀐다. 손익(`balance - buyInTotal`)은 부호별
  win/accent 색으로 별도 표기.

### 이번 판 액션 로그 (`round-log.tsx`)

- 상태 배지는 `pending`(승인 대기, warn) · `rejected`(거절됨, accent) · `reverted`(정정됨, muted)만
  표시한다. `accepted`는 배지 없음 — 기본값이라 예외만 눈에 띄게 한다는 의도가 코드 주석에
  명시돼 있다.
- 대리 입력된 액션은 `(대리: {이름})`을 인라인으로 붙인다.

### 액션 바 (`action-bar.tsx`)

화면 하단 고정(`fixed inset-x-0 bottom-0`), `env(safe-area-inset-bottom)` 반영.

- 버튼 5개, `grid-cols-5`: 체크 · 콜 · 레이즈 · 다이 · 올인. 기존 문서의 "다이/콜/레이즈/올인
  4버튼"은 실제와 다르다 — 체크가 추가로 있다.
- 금액은 프리셋 칩(5/10/25/50) + 숫자 입력 필드 하나. "+1k/+5k/×2" 같은 프리셋은 구현에 없다.
  올인은 프리셋 금액을 쓰지 않고 항상 `self.balance` 전액으로 계산한다.
- 라운드가 없으면(`snapshot.currentRound === null`) 전 버튼이 비활성 + `disabledReason`
  "딜러가 판을 시작하면 베팅할 수 있습니다"로 통일된다. 잔액 부족은 콜/레이즈/올인 개별로
  다른 이유 문구를 붙인다.
- 제출은 `crypto.randomUUID()`로 클라이언트가 멱등키를 만들어 `placeBet` 서버 액션 호출 →
  성공 시 `refetch()` 후 `bet.placed` 브로드캐스트. 실패하면 `runAction`이 토스트로 에러를
  보여주고 그 외 상태 변경은 없다(낙관적 UI 반영이나 롤백 애니메이션은 없다 — 성공 전에는
  화면이 먼저 바뀌지 않는다).

### 딜러 컨트롤 (`dealer-panel.tsx`)

`self.role === 'host' || 'dealer'`가 아니면 컴포넌트 자체가 렌더되지 않는다(숨김 게이팅,
서버 재검증은 각 Server Action이 담당 — `07-auth-and-security.md`). 대기열이 상단에 붙는
오버레이가 아니라 참가자 그리드/로그 아래 고정 패널로 붙는다.

포함 기능:
- 판 시작 / 판 종료(승자 선택 서브뷰로 전환) / 판 무효(재경기)
- 세션 정산(`closeRoom`) — `window.confirm()` 네이티브 다이얼로그로 확인. 방장(`isHost`)만
  보이고, 끝난 판이 하나도 없으면 비활성 + 사유
- 승인 대기열 — 건별로 승인/거절 버튼. 거절은 사유 입력 필드가 펼쳐지고 사유 없이는
  확정 버튼이 비활성
- `<details>`로 접는 부가 도구: 확정 액션 정정(최근 5건), 추가 바이인, 대리 입력(폰 없는
  참가자용), 역할 변경(방장 전용, `RoleForm`은 `isHost`일 때만 렌더)

판 종료 승자 선택은 같은 패널 안에서 모드 전환(`idle` → `pickWinner`)으로 처리한다 — 별도
화면 이동이 아니다. 승인 대기 건이 있으면 판 종료 버튼이 비활성 + "승인 대기 베팅을 먼저
처리하세요"로 막힌다.

## 족보 Advisor (`/advisor`)

기존 문서는 이를 판 화면 안의 바텀시트로 서술했지만 **실제로는 독립 페이지**다
(`advisor/page.tsx` → `AdvisorClient`). 방 화면에 "족보 보기" 버튼이나 시트 진입점은 없다.

구성:
- 게임 종류 토글(섯다/고스톱) — 전환 시 선택 카드 초기화
- 판정 결과 패널: 섯다는 카드 2장 필수, 고스톱은 획득 패 전체 + 고/흔들기/폭탄 스테퍼
- 사진 인식 버튼: `visionEnabled`(서버에서 `JOKBO_VISION_ENABLED && ANTHROPIC_API_KEY` 계산,
  `advisor/page.tsx`)가 false면 버튼이 항상 비활성 + `disabledReason`
  "사진 인식이 꺼져 있습니다 (ANTHROPIC_API_KEY 필요)" — 버튼 자체를 숨기지 않는다
- 카드 그리드(`card-picker.tsx`): 월별로 행을 나눠 표시. 섯다는 `deckFor('seotda')`가
  1~10월만 반환하므로 11·12월 행이 아예 없다(비활성이 아니라 존재하지 않음). 고스톱은
  4열, 섯다는 2열
- 결과는 선택이 바뀔 때마다 `useMemo`로 즉시 재계산된다 — 확정 버튼 없음

인식 실패(카드 0장)나 서버 에러는 토스트로만 처리한다. 인식 성공 시 확신도(`confidence`)를
토스트 문구에 백분율로 노출하고, 90% 미만이면 info 톤, 이상이면 success 톤으로 구분한다.
인식 결과는 선택 상태를 덮어쓸 뿐이라 언제든 그리드에서 다시 고쳐 선택할 수 있다.

## 상태 처리

Next.js 라우트 레벨 `loading.tsx`가 없으므로 로딩 상태는 각 클라이언트 컴포넌트가
`useTransition`의 `isPending`으로 직접 표현한다(버튼 라벨을 "만드는 중…" 등으로 바꾸는 방식이
대부분, 별도 스켈레톤 레이아웃은 없음). `Spinner` 컴포넌트(`components/ui.tsx`)는 현재
Advisor의 사진 인식 버튼 한 곳에서만 쓰인다.

| 상황 | 실제 처리 |
|------|------|
| 방 없음 | `ErrorScreen` "방을 찾을 수 없습니다" + 홈 버튼 |
| 방 종료됨 | `/rooms/[code]/result`로 즉시 redirect (에러 화면 거치지 않음) |
| 입장 거부 | `ErrorScreen` "입장할 수 없습니다" + 서버가 반환한 에러 메시지 그대로 |
| 스냅샷 조회 실패 | `ErrorScreen` "방 상태를 불러오지 못했습니다" |
| 방 목록/랭킹/판 기록 빈 배열 | `EmptyState` (제목 + 선택적 hint) |
| 실시간 연결 끊김 | 헤더에 `Badge tone="warn"` "연결 끊김"만 표시. 재연결 시도 문구·로컬 액션 큐는
  구현에 없다 — 끊긴 동안 액션을 제출하면 서버 액션 실패로 처리될 뿐이다 |
| 서버 액션 실패 전반 | `runAction`이 토스트(error 톤)로 에러 메시지 노출, 상태는 변경하지 않음 |

기존 문서에 있던 "네트워크 끊김 시 액션이 로컬 큐에 쌓인다"는 서술은 구현과 다르다 — 현재는
배지 표시만 하고 큐잉은 없다.

### 토스트 vs 다이얼로그

커스텀 다이얼로그 컴포넌트는 존재하지 않는다. 되돌리기 어려운 액션(세션 정산)의 확인은
`window.confirm()` 네이티브 브라우저 다이얼로그 하나뿐이다(`dealer-panel.tsx`의 `closeRoom`
호출부). 그 외에는 전부 토스트다.

`ToastProvider`(`components/ui.tsx`):
- 톤 3종만 존재: `info` / `error` / `success` (경고 전용 톤 없음)
- 최대 3개까지 동시 표시(`slice(-2)` + 신규), 3.5초 후 자동 소멸
- 화면 상단 중앙 고정, `pointer-events-none` 배경 위에 토스트만 클릭 가능

실제 토스트 트리거:

| 이벤트 | 톤 |
|---|---|
| 방 생성/베팅/승인 등 서버 액션 실패 | error |
| 내 베팅이 거절됨 (`bet.rejected` 브로드캐스트 수신, 본인 액션일 때만) | error |
| 판 시작 (`round.started` 브로드캐스트) | info |
| 판 종료·승자 결정 (`round.ended` 브로드캐스트) | success |
| Advisor 사진 인식 완료 | 확신도 90% 미만 info, 이상 success |
| Advisor 인식 카드 0장 | error |

## 권한 게이팅

실제 구현은 2단계로 나뉜다(기존 문서의 "숨김/비활성+툴팁/거부 표면" 3단계 중 페이지 전체를
막는 거부 표면 사례는 코드에 없다 — 비멤버 접근은 자동 입장을 시도하고, 실패하면 에러 화면일
뿐 별도의 "거부 표면" UI 패턴은 구현돼 있지 않다).

| 단계 | 구현 방식 | 예시 |
|------|-----------|------|
| 숨김 | 컴포넌트가 조건부로 아예 렌더되지 않음 | `DealerPanel`은 host/dealer가 아니면 렌더 안 함. `ActionBar`는 observer면 렌더 안 함. `RoleForm`은 host가 아니면 렌더 안 함 |
| 비활성 + 사유 | `Button`의 `disabled` + `disabledReason` prop → `title` 속성으로 노출(호버/롱프레스 시 표시, 상시 보이는 툴팁 아님) | 라운드 없을 때 액션 바 전체, 잔액 부족, 대상 미선택, 사유 미입력 상태의 확정 버튼 |

버튼을 숨기거나 비활성화하는 것은 **편의이지 보안이 아니다.** 서버는 각 Server Action에서
항상 재검증한다(`07-auth-and-security.md`).

## 인터랙션 규칙

- hover 의존 UI 없음. `<details>`(부가 도구 접기)와 클릭 토글(거절 사유 입력창)만 사용.
- 탭 타깃: `Button`은 `size="sm"` 36px(`min-h-9`) / `md` 48px(`min-h-12`) / `lg` 56px(`min-h-14`).
  액션 바 버튼은 `md`(48px) 사이즈를 쓴다 — 문서에 있던 "56px 이상"은 실제로는 `lg` 사이즈에만
  해당하고 액션 바 기본 버튼에는 적용되지 않는다.
- 파괴적 액션(다이는 danger 톤, 올인은 warn 테두리)은 색으로 구분하되 액션 바 안에서 물리적
  위치는 다른 버튼과 동일한 그리드 안에 나란히 있다 — 별도로 멀리 떨어뜨리진 않는다.
- 팝오버성 UI(거절 사유 입력, 승자 선택 서브뷰)는 레이아웃 안에서 확장되며 별도 오버레이로
  뜨지 않는다.

## 접근성 · 실사용

- 색만으로 상태를 전달하지 않는다 — 상태 배지는 항상 색 + 텍스트 라벨 조합.
- 다크 테마 전용. 라이트 테마 대응 코드는 없다(`globals.css`에 `prefers-color-scheme` 분기 없음).
- 화면 꺼짐 방지(wake lock) 관련 코드는 현재 없다 — 미구현.

## 시각 변경 확인

눈에 보이는 UI 변경은 커밋·푸시 전에 사용자 확인을 받는다. 이 규칙은 구현 단계에서 적용된다.
