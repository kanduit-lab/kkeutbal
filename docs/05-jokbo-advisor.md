규칙 자체는 `04-game-engines.md`가 소유한다. 이 문서는 **카드를 어떻게 입력받는가**만 다룬다.

## Context

초심자가 있으면 판이 멈춘다. 특히 섯다 특수패(알리·독사·세륙…)와 고스톱 점수 계산.
"내 패가 뭔지" 즉시 알려주는 것이 목적이며, **전략 조언(콜/다이 추천)은 범위 밖**이다 —
그건 판을 재미없게 만들고, 돈이 안 걸린 놀이의 취지에도 어긋난다.

## 두 개의 입력 경로

```
                  ┌─────────────────┐
   수동 피커 ────►│                 │
                  │  HwatuCard[]    ├──► 엔진 evaluate() ──► 결과 표시
   사진 인식 ────►│  (정규화된 카드) │
                  └─────────────────┘
                          ▲
                          └── 사용자가 언제든 수정 가능
```

핵심 규칙: **인식은 수동 입력의 대체가 아니라 초기값 채우기다.**
인식 결과는 항상 피커에 반영되고, 사용자가 확정 버튼을 눌러야 판정이 확정된다 (요구 R5.3).
인식이 죽어도 앱은 100% 동작한다.

## 경로 1 — 수동 카드 피커

기본 경로이며 오프라인에서도 동작한다.

- 12개월 × 카드 그리드. 게임이 섯다면 1~10월 20장만 활성화한다.
- 선택 개수 제한: 섯다 2장, 고스톱은 제한 없음(획득 패 집합).
- 선택 즉시 판정 결과가 갱신된다. 확정 버튼 없이도 미리보기가 뜬다.
- 최근 선택한 조합을 로컬에 기억해 재입력 부담을 줄인다.

카드 식별은 `HwatuCard.id` 문자열로만 한다. UI 상태·인식 출력·DB 저장이 전부 같은 키를 쓴다.

## 경로 2 — 사진 인식 (Claude vision)

### 파이프라인

```
카메라/앨범 촬영
  → 클라이언트 리사이즈 (장변 1568px, JPEG q=0.8)
  → Server Action 업로드 (multipart)
  → 서버: 크기·MIME·해상도 검증
  → Anthropic Messages API (vision) 호출, 구조화 출력 강제
  → 응답을 zod 로 파싱 → HwatuCard[] 로 정규화
  → 인식 실패/저신뢰 카드는 '미확정'으로 표시
  → 피커에 프리필 → 사용자 확인
```

- 모델: `claude-sonnet-5` (env `JOKBO_VISION_MODEL`). 저신뢰·재시도 시 `claude-opus-4-8`로 승격.
- 클라이언트에서 먼저 리사이즈하는 이유: 업로드 시간과 토큰 비용이 이미지 크기에 직결된다.
- **API 키는 서버에만 둔다.** 브라우저에서 Anthropic API를 직접 호출하지 않는다.

### 출력 계약

모델에게 자유 서술을 시키지 않는다. 카드마다 월·종류·신뢰도를 요구한다.

```ts
const VisionResult = z.object({
  cards: z.array(z.object({
    month: z.number().int().min(1).max(12),
    kind: z.enum(['gwang', 'yeol', 'tti', 'pi']),
    confidence: z.number().min(0).max(1),
    note: z.string().optional(),        // 가림·흐림 등 인식 저해 요인
  })),
  imageQuality: z.enum(['good', 'fair', 'poor']),
})
```

서버는 파싱 후 `(month, kind)`를 실제 덱 카드로 매핑한다. 덱에 없는 조합·중복 카드는 버리고
`미확정`으로 넘긴다. **모델 출력은 신뢰 경계 밖이다** — 파싱 전 어떤 값도 상태에 반영하지 않는다.

### 신뢰도 처리

| confidence | 처리 |
|------------|------|
| ≥ 0.9 | 피커에 선택된 상태로 프리필 |
| 0.6 ~ 0.9 | 프리필하되 노란색 '확인 필요' 표시 |
| < 0.6 | 프리필하지 않고 후보만 제시 |

`imageQuality === 'poor'`면 재촬영 가이드(조명·정면·전체가 보이게)를 먼저 띄운다.

### 비용·남용 방지

- 사용자당 분당 호출 상한을 서버에서 적용한다.
- 동일 이미지 해시는 캐시해 재호출하지 않는다.
- `JOKBO_VISION_ENABLED=false`면 업로드 UI 자체를 숨긴다 (수동 피커는 계속 동작).
- 인식 요청·결과·신뢰도를 기록해 오인식 패턴을 추적한다 (`hand_records.source='vision'`).

## 가시성 규칙

- 내 손패 판독 결과는 **나에게만** 보인다. 실시간 채널로 브로드캐스트하지 않는다
  (`03-realtime-protocol.md` 보안 경계).
- 판이 끝난 뒤에만 `hand_records`가 방 참가자에게 공개된다.
- Advisor 사용 여부 자체도 다른 참가자에게 노출하지 않는다 — 노출되면 "쟤 족보 몰라"가 되어
  쓰기 싫어진다. 도구는 눈치 안 보고 쓸 수 있어야 한다.

## 실패 모드

| 실패 | 동작 |
|------|------|
| 네트워크 오류 | 수동 피커로 즉시 전환, 재시도 버튼 제공 |
| API 키 미설정 | 업로드 UI 숨김. 앱은 정상 동작 |
| 카드 0장 인식 | 재촬영 가이드 + 수동 입력 유도 |
| 실제와 다른 카드 인식 | 사용자가 피커에서 수정. 수정 이력을 오인식 로그로 남김 |
| 응답 스키마 불일치 | 결과 폐기, 사용자에겐 "인식 실패"로 표시 (부분 반영 금지) |

## 수용 기준

- [ ] 인식 기능을 완전히 꺼도 족보 판독이 100% 가능하다.
- [ ] 인식 결과가 틀렸을 때 탭 2회 이내로 수정 가능하다.
- [ ] 모델 응답이 스키마를 벗어나면 어떤 값도 상태에 반영되지 않는다.
- [ ] 손패 결과가 판 종료 전에 다른 참가자에게 노출되지 않는다.
