## 전제

이 앱은 **실제 MT 날짜에 동작해야 의미가 있다.** 따라서 "완성도"가 아니라
"그날 판이 돌아가는가"를 기준으로 자른다. 못 끝낸 기능은 수동 대체 경로가 있어야 한다.

칩은 실물로 쓰므로 **앱이 없어도 게임 자체는 돌아간다.** 그래서 메인은 승패 기록과 족보 판독이고,
원격 베팅은 실물 칩이 모자랄 때 쓰는 보조다. 단계 순서는 기술 의존성을 따르되,
일정이 밀리면 베팅보다 기록·족보를 먼저 살린다.

## MVP 경계

```
┌─ MVP (이것만 되면 MT에서 쓸 수 있다) ──────────────┐
│  Phase 1  화투 카드 모델 + 섯다 엔진               │
│  Phase 2  인증 + 스키마 + RLS                      │
│  Phase 3  방 생성/입장 + 실시간 동기화             │
│  Phase 4  베팅 + 칩 원장 + 예산                    │
│  Phase 5  족보 Advisor (수동 피커)                 │
│  Phase 6  세션 정산 + 랭킹                         │
└────────────────────────────────────────────────────┘
   Phase 7  사진 인식 (vision)        ← 없어도 수동으로 됨
   Phase 8  고스톱 엔진               ← 없으면 섯다만 진행
   Phase 9  E2E · 리허설 · 폴리시     ← MVP 직후 필수
```

MVP에서 **고스톱과 vision을 뺀 이유**: 둘 다 대체 경로가 존재한다(섯다로 진행 / 손으로 입력).
반면 실시간 동기화·칩 원장은 대체 경로가 없다. 없으면 앱을 쓸 이유 자체가 사라진다.

## Phase 0 — 스캐폴드 ✅

저장소 초기화, 설계 문서, 프로젝트 구조, 도메인 타입, 설정 파일.
이 커밋 시점 완료.

## Phase 1 — 도메인 코어

- 화투 48장 카드 데이터 확정 (`features/hwatu/cards.ts`)
- 섯다 엔진 TDD: 190조합 기대값 테이블 먼저 → 엔진 구현
- 상대 판정(암행어사·땡잡이·구사) 룰 토글 반영

**완료 기준**: `pnpm test` 통과, 섯다 커버리지 90%+.
DB·네트워크 없이 순수 함수만으로 검증 가능해야 한다.

## Phase 2 — 인증 · 데이터

- Authentik OIDC 애플리케이션 등록, Auth.js v5 연동
- Drizzle 스키마 반영, RLS 정책 적용
- Supabase JWT 브리지 확정 (`07-auth-and-security.md` Open Question 해소)

**완료 기준**: 로그인 후 본인 `users` 행 생성, 비참가자 조회 시 0행 확인.

## Phase 3 — 방 · 실시간

- 방 생성/입장(코드·QR), 참가자 목록(Presence)
- Broadcast 채널 구독, 이벤트 envelope + zod 검증
- 재접속 시 Postgres 전량 복원, `state.snapshot` 경로

**완료 기준**: 2기기 동기화 p95 300ms 이내, 강제 종료 후 상태 완전 복원.

## Phase 4 — 베팅 · 예산

- 액션 제출(낙관적 UI) → Server Action 확정
- 승인 모드 대기열, 거절 사유, 정정(revert)
- 칩 원장 append-only, 잔액 도출, 바이인·경고 임계값

**완료 기준**: 순손익 합계 0 불변식 검증 통과, 잔액 초과 베팅 이중 차단.

## Phase 5 — 족보 Advisor (수동)

- 화투 카드 피커 UI, 게임별 덱 필터·선택 개수 제한
- 실시간 판정 결과 표시, 본인 한정 가시성

**완료 기준**: 오프라인에서도 판독 동작, 결과 수정 탭 2회 이내.

## Phase 6 — 정산 · 랭킹

- 세션 종료 → 순손익 확정 → 결과 화면
- 세션/누적 랭킹, 재미 지표 배지

**완료 기준**: 지표 정의(`06-features-...md`)와 계산 결과 일치, 참여 0판 승률 `-` 표기.

---

## Phase 7 — 사진 인식

- 클라이언트 리사이즈 → Server Action 업로드 → Claude vision
- 구조화 출력 zod 파싱, 신뢰도별 프리필, 호출 상한·캐시

**완료 기준**: 인식을 꺼도 앱 100% 동작, 스키마 이탈 시 부분 반영 0건.

## Phase 8 — 고스톱

- 점수 파이프라인 구현, 룰 프리셋 토글
- 간이 모드(점수만 입력) / 정밀 모드(패 입력) 결정 후 반영

**완료 기준**: 경계값·배수 조합 테스트 통과, `breakdown` 근거 표시.

## Phase 9 — 검증 · 리허설

- Playwright E2E: 2컨텍스트 동기화, 재접속, 정산
- 모바일 실기기 확인 (한 손 조작, 어두운 조명)
- **실제 판 리허설 1회** — 실물 화투로 3판 이상 돌려보기

**완료 기준**: 리허설에서 수동 개입(개발자 콘솔·DB 직접 수정) 0회.

---

## 릴리스

- 태그는 MVP 완료 후 `v0.1.0`부터. 그 전에는 태그를 붙이지 않는다.
- 리허설 전 배포는 프리뷰 환경에서만 확인한다.

## 리스크 순서

가장 먼저 깨질 것부터 검증한다.

1. **실시간 지연·유실** — Phase 3에서 조기 측정. 여기서 막히면 아키텍처 재검토.
2. **RLS 격리** — Phase 2에서 확인. 늦게 발견하면 전 테이블 수정이 된다.
3. **섯다 규칙 정확도** — Phase 1. 실제 플레이 그룹 룰과 1회 대조 필요.
4. **현장 네트워크** — Phase 9 리허설. 완화책은 로컬 큐 + 스냅샷 복원.
